# Suite implementation

This document describes the implementation on `main`. [gaps.md](gaps.md) remains the historical assessment of the original MVP preserved on `main-mvp`; its source references describe that baseline, not the current suite. The new suite uses fresh databases and volumes and provides no MVP data import.

## Product decisions

One company per deployment; public, accountless reports; English and Indonesian. Contacts are optional and hidden from all application staff. OTP confirms destination control, not legal identity. Reporter recovery uses a separately saved recovery secret, never an email or phone lookup. Staff use local passwords and mandatory authenticator MFA. System administrators manage the company but cannot read case narratives or evidence. Managers review cases in their current team; analysts need a current team membership and explicit assignment. Recusal removes access. Leadership or review-team allegations go to an independent restricted team with no overlapping memberships. A different manager must approve closure.

The assistant is optional and off by default. Both company enablement and server-recorded reporter consent precede processing. Only the reviewed report is published to staff. Evidence originals remain sealed in the private service; staff receive only scanned, sanitized, reporter-approved derivatives. Retention is mandatory company configuration in production. Legal holds suspend deletion. Delivery uses SMTP and Twilio Messaging. Operations target a Docker VPS with offsite encrypted restic backups.

## Verification boundaries

Local verification covers real PostgreSQL migrations, API authorization/security scenarios, type checking, production builds, desktop/mobile browser flows, Mailpit SMTP delivery, and the actual ClamAV/converter evidence pipeline. Test bodies use synthetic data. The case/privacy integration harness bridges the service HTTP boundary in-process; browser and evidence smoke tests exercise the actual Docker network and runtime database accounts.

An isolated offsite-style SFTP/restic backup and restore drill exercises both databases, sealed evidence, encryption keys, audit checkpoints, and session revocation. The destination used for this drill is a local test container; it does not establish availability or permissions of the company's real offsite destination.

Production acceptance still requires the company's real SMTP/Twilio delivery, provider policy review for optional MiniMax, actual DNS/TLS/firewall/logging review, pinned release images and vulnerability scanning, encrypted host disks, offsite backup permissions and scheduling, and an observed restore drill on the target infrastructure. These are deployment checks requiring company infrastructure and credentials, not claims made by the local test suite.

## Limits to communicate honestly

- Narrative, circumstances, message timing, and visible evidence may identify someone despite contact isolation. Reporters must review every page; sanitization cannot infer every identity clue.
- Privileged host/database/key operators and delivery providers are outside the application-role anonymity boundary. Separating operational access and protecting hosts/backups remains necessary.
- Losing both saved reporter secrets makes a case unrecoverable. No staff override reveals or recreates access. Reloading an unsaved receipt also loses its memory-only secrets.
- Redaction flattens PDF/Office documents to images, removing selectable text, signatures and interactive content. Originals are preserved sealed while retention or legal hold applies; ordinary staff cannot retrieve them.
- An interrupted submission can be retried in the same page using memory-only credentials. Reloading that page discards them. Retired submission IDs remain in the deletion manifest and cannot recreate erased cases.
- Generic notification content must stay generic. Company administrators are responsible for policy/template wording and retention choices.
- Audit chains detect modification relative to retained checkpoints. A database/host owner can still replace local history; secure independent offsite checkpoint access is necessary.
- Backup snapshots containing held cases are kept until an authorized hold review. Deletion cannot remove expired personal data from an immutable held snapshot; restoration must replay the newest deletion and hold manifests before public access.
- Browser tests cover Chromium desktop and a mobile viewport, keyboard form controls, labels and layout. They do not replace a full assistive-technology or independent penetration test.
